# 交接收尾报告

每次流程结束都给用户一份先结论、后短表的中文报告。最多一张主表和三个短列表；路径使用可点击的绝对路径。报告必须区分实际执行、建议配置和未验证边界。

## 共同主表

| 项目 | 结果 |
|---|---|
| 场景 / 方向 | 设备交接或对话交接 / 交出或接收 |
| 状态 | READY / READY_WITH_LIMITS / DRAFT / BLOCKED |
| 交接入口 | `交接/README.md` 的绝对路径 |
| 批次 | `handoff_id`，前序批次（如有） |
| 任务 | 当前任务 ID、下一动作 |
| 模型 | 实际主代理模型/强度（无法确认则写“未确认”） |
| 配置 | 设备：清单与恢复状态；对话：未采集 |
| Git / 云端 | 实际检查、提交、推送结果；未执行写原因 |
| 本机独有内容 | 尚未传走的必要文件及保存方式；没有时写“未发现” |

## 结果段落

- 已完成：入口、任务账本、导航、环境/证据、归档登记、适用配置和校验的实际结果。
- 未完成或未验证：按影响排序写出原因、证据和下一步；不能用“无异常”替代。
- 下一方第一步：只写一条可执行动作，并链接入口。
- 需用户处理：只列权限、秘密设置、冲突选择或远端绑定等真正阻塞。

状态含义：

- `READY`：本场景必需文件、状态和适用验证齐全。
- `READY_WITH_LIMITS`：可接续，但有设备、凭证、远端或环境限制，限制已写明。
- `DRAFT`：仅形成部分摘要，不能安全接续。
- `BLOCKED`：必须由用户或外部环境解决，继续会造成误导或数据风险。

设备未推送时必须写“本地交接包已就绪，远端同步未完成”；仅生成配置示例时必须写“真实凭证需在新设备手动设置”。实际模型/强度和前置建议分开，不把建议写成已切换事实。

附一条用户可复制的接管提示：“请读取项目根目录的 `交接/README.md`，本次是【设备/对话】交接的接收，先核对包与实际工作区，按任务交接中的第一动作继续；核心规范保持不变，归档仅供追溯。”不要在提示中夹带真实密钥或声称本次未执行的配置已经部署。
