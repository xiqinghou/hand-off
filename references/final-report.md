# 交接收尾报告

每次流程结束都给用户一份先结论、后短表的中文报告。最多一张主表和三个短列表；路径使用可点击的绝对路径。报告必须区分实际执行、建议配置和未验证边界。

## 共同主表

| 项目 | 结果 |
|---|---|
| 场景 / 方向 | 设备交接或对话交接 / 交出或接收 |
| 状态 | READY / READY_WITH_LIMITS / DRAFT / BLOCKED |
| 交接入口 | `交接/README.md` 的绝对路径 |
| 批次 | `handoff_id`，前序批次（如有） |
| 任务 | 当前任务 ID、计划待办及上次中断进度 |
| 模型 | 实际主代理模型/强度（无法确认则写“未确认”） |
| 配置 | 设备：云端脱敏资料 / 本地私密包 / 目标设备恢复状态分别列出；对话：未采集 |
| Git / 云端 | 实际检查、提交、推送结果；未执行写原因 |
| 本机独有内容 | 尚未传走的必要文件及保存方式；没有时写“未发现” |

## 结果段落

- 已完成：入口、任务账本、导航、环境/证据、归档登记、适用配置和校验的实际结果。
- 未完成或未验证：按影响排序写出原因、证据和下一步；不能用“无异常”替代。
- 下一方第一步：只写一条可执行动作，并链接入口。
- 需用户处理：只列权限、秘密设置、冲突选择或远端绑定等真正阻塞。

状态含义：

- `READY`：本场景必需文件、状态和适用验证齐全。
- `READY_WITH_LIMITS`：可接续，但有设备、凭证、远端或环境限制，限制已写明。
- `DRAFT`：仅形成部分摘要，不能安全接续。
- `BLOCKED`：必须由用户或外部环境解决，继续会造成误导或数据风险。

设备未推送时必须写“本地交接包已就绪，远端同步未完成”。生成完整本地恢复包时，给出 `交接/配置交接/.codex/` 可点击绝对路径，说明包含实际 API 配置、未上传、需要用 U 盘带走，并提醒隐藏目录的显示方式。只生成脱敏示例或真实配置缺项时，明确缺失项及恢复动作；不能仍要求用户逐个寻找已经打包的凭据。区分已生成、用户已复制、目标已恢复、服务实测可用，未经验证不能合并成“配置完成”。实际模型/强度和前置建议分开，不把建议写成已切换事实。

交出时附一条简单接收指令：已唤出 `$hand-off` 后说“帮我接手来自另一台设备的交接资料”（对话场景换成“另一个对话”）。路径、校验和阅读顺序由 Skill 处理，不要求用户写长提示。

## 接收后的简报

设备与对话接收都要给用户简洁说明，主表按本场景删去不适用行，必要时用下面的小表替代宽表：

| 接收事项 | 结果 |
|---|---|
| 已接收资料 | 项目与规则入口、唯一计划、任务进度、关键决定时间线、环境/验证证据；只列实际读到的内容 |
| 计划中尚未完成 | 任务 ID、目标、依赖与推荐顺序；过多时给数量、首项并链接任务账本 |
| 上次中断任务 | 停止步骤、最后成功点、剩余动作；没有时写“未发现中断任务” |
| 疑问或限制 | 缺失资料、状态冲突、未验证环境及其影响；没有时写“未发现影响接续的疑问” |
| 续作首项 | 收到“继续”后将执行的具体任务 ID、首动作与完成判断 |

默认以“交接已接收，尚未开始执行待办。你说‘继续’后，我会从 T-xxx 的……开始；也可以指定‘继续 T-yyy’。”结束。不能用‘任务已完成’表达‘交接已接收’，也不能将接收指令当成开发授权。若本次指令已明确包含接手并继续，则按授权执行，收尾改为报告实际续作结果。

用户随后说“继续”时，以本次简报指定首项、依赖顺序和当前工作区为准，先解决已声明会阻塞该任务的缺口，再执行；不要重启已验收步骤或恢复退役计划。候选任务存在真实冲突且简报未确定首项时，仅澄清该选择，其他已明确的工作可继续。
