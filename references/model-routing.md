# 模型、强度与子代理分工

## 必须先提醒用户

场景确定后、实质执行前，主代理发送简短提醒，包含：

- 建议的主模型与推理强度；
- 依据本次场景和风险的一句理由；
- 是否使用子代理及大致分工；
- 当前实际配置能否确认，是否需要用户手动切换。

示例：“本次属于多轮历史资料的设备交接，建议主代理使用 GPT-6-astra / high；它负责计划冲突与最终放行。文件与任务盘点可交给 GPT-6.1-sol / medium。当前主代理配置如无法核实，请在界面确认；我不会把建议当成已切换。”

已有用户指定配置优先；可胜任时不强制换模型。轻量任务不要求升级。不能切换主代理时如实说明，是否切换由用户决定；不要反复询问已明确的偏好。实际能力不足或缺工具时，只暂停依赖它的动作。

## 建议组合

以下是面向本技能的工程建议，不是官方保证，也不是经过本技能性能评测的结论。先检查目标环境可用模型和支持的强度；不认识或不可用的模型不硬设、不自动替换计费配置。

| 场景/角色 | 建议模型 | 强度 | 使用条件 |
|---|---|---|---|
| 普通同项目对话交接 | gpt-6.1-sol | medium | 目标明确、少量改动、单一计划；通常一个代理足够 |
| 常规设备交接 | gpt-6.1-sol | high | 已有清晰计划，需整理环境、配置、归档与同步 |
| 多次迁回、计划冲突、分支分叉、迁移异常的主协调 | gpt-6-astra | high | 需要跨资料判断和最终放行；当前这类多轮交接适用 |
| 文件导航/历史计划/任务证据盘点 | gpt-6.1-sol | medium | 只读调查，输出事实、路径、缺口和置信边界 |
| 配置与跨平台恢复审查 | gpt-6.1-sol | high | 审查路径、秘密、插件/Skill 依赖；不带回秘密值 |
| 独立验收 | gpt-6.1-sol | high | 不由写入者自证；复杂矛盾交主协调处理 |
| 机械计数/hash/目录核对 | 优先本地脚本；可用 gpt-6-luna | medium | 结果可确定验证；不让轻量代理独自决定归档或提交 |

不默认使用 xhigh/max；只有 high 下出现实质难题且提高推理有望改善时升级。简单任务不靠增加代理或强度制造成本。

## 何时并行

至少有两个可独立调查的方向、不会相互修改同一文件，才考虑并行。不能仅因文件很多就派发；沟通和复核成本也要计入。

推荐最多“一个主代理 + 两到三个调查代理”，受当前并发能力限制：

- 文件组：导航、历史入口、引用和归档候选。
- 任务组：整体计划、活动任务、未完成义务与证据版本。
- 环境组：配置白名单、工具版本、Git/恢复风险，只读审查。
- 最后复用一个空闲槽位做独立验收，不与最终写入同时进行。

本技能建议子代理仅返回结构化发现：相对路径、事实、证据、待核实项、建议。主代理统一写入口、移动归档、恢复配置、暂存/提交/推送；不同时运行多个有副作用的 Git 或配置操作。

## 调度约束

- 仅在用户或适用规则允许代理分工且工具实际可用时执行；不可用则串行完成并如实记录。
- 子代理使用实际代理工具，而非创建用户侧边栏里的新对话。发消息给另一个用户对话须有用户授权。
- 不同子代理可以指定模型和强度，但以当前工具 schema 为准；若完整历史继承模式不支持覆盖模型，使用独立上下文并提供最小足够任务，不伪装已覆盖。
- 派发内容只含所需项目路径、当前用户要求、只读范围、验收目标；不把整个凭证文件发给子代理。
- 记录实际模型、强度、任务、输出和验收结果；继承或无法确认时写清，不声称使用了推荐配置。
- 子代理冲突由主代理核实源文件解决，不按多数票采信。
