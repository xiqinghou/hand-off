# 设备交接流程

设备交接用于换设备、迁回或离开当前设备后在另一台设备继续。它必须生成可脱离当前对话阅读的 `交接/`，并按固定命名规则输出。

## A. 交出设备

1. **只读基线**：读取项目 `AGENTS.md`、现行文档入口和当前 `交接/README.md`（如有）；记录项目路径、分支、HEAD、remote、Git/运行时版本；运行 `git status --short`、`git diff --check`，必要时记录 diff 统计。保留已有修改、删除和未跟踪文件。
2. **更新固定文件**：维护 `README.md`、`工作交接/任务交接.md`、`文件导航.md`、`环境与验证.md`、`归档索引.md`、`接收回执.md`；在任务交接的“对话关键结论”中保存尚未落入代码或正式文档的有效要求、决定理由与未决事项，并按目录契约记录关键时间线和取代关系。只保留一个当前计划入口；不再创建“最新方案/最终方案/当前交接”等并列文件。
3. **整理旧材料**：盘点旧计划和旧交接的未完成事项，先映射到任务 ID，再将安全的阶段材料移入 `工作交接/归档/<handoff_id>/`；项目规范、原始资料和受规则保护文件不覆盖、不改名，改在归档索引登记。
4. **配置交接**：按 [配置流程](config-handoff.md) 生成可上传的脱敏清单和恢复步骤。用户授权携带真实 API 密钥时，先确认 Git 忽略且未跟踪，再生成 `交接/配置交接/.codex/` 最小本地恢复包，供 U 盘复制。复制本 Skill 到可上传的 `配置交接/skills/hand-off/`，并在本地恢复包中携带 `.codex/skills/hand-off/`；排除系统杂项、缓存和父目录，普通文档与 Skill 不得夹带密钥。
5. **校验与 Git**：先运行校验脚本和秘密扫描，再按 [Git 流程](git-handoff.md) 检查、暂存、提交或推送。用户明确授权的完整设备交接可以继续执行对应 Git 动作；未授权时停在本地就绪。
6. **收尾**：按 [收尾报告](final-report.md) 给出状态、云端结果、本地恢复包的可点击路径和下一设备第一步。明确 U 盘需要复制隐藏的 `.codex` 目录，区分“已生成”和“用户已复制”；推送失败或未执行时不得称为“已部署”。

## B. 新设备接收

1. “帮我接手来自另一台设备的交接资料”即设备接收。默认在当前项目根目录找 `交接/README.md`；用户给了路径则优先使用。找不到、存在多个项目或项目尚未拉取时才补问路径/仓库。先核对分支、实际 HEAD、工作区和本地未提交改动；不覆盖已有修改。
2. 只读入口，按其中链接读取 `工作交接/任务交接.md`、`文件导航.md`、`环境与验证.md`、`归档索引.md` 和配置说明，提取当前有效决定及被取代的历史要求。
3. 运行校验脚本。云端包不要求本地私密目录；U 盘恢复包位于约定路径时加 `--private-config` 核验本地清单。失败先报告，不重建清单掩盖差异；绝对源路径只作为环境提示。
4. 按配置说明核对恢复状态。用户已在启动前恢复配置时不重复覆盖。仍需恢复时先备份，复制清单中同名文件并保留目标原有其他内容，不能删除替换整个用户配置目录。Skill 的发现目录、系统路径、环境变量和依赖按目标设备复核；分别记录“已复制”和“实测可用”。
5. 核对计划中的待办与上次中断任务的最后成功点、剩余步骤、依赖、证据及建议首项。只做接收必需的基线检查，默认等待用户“继续”后执行未完成工作；不要从归档恢复已退役计划。用户本次已要求接手并继续时直接按其授权续作。
6. 填写 `工作交接/接收回执.md`，新增接收方的路径、HEAD、校验结果、配置恢复结果、任务理解和冲突；保留交出方快照。按收尾模板向用户说明已接收哪些内容、待办/中断进度、疑问及下一步，明确收到“继续”后从哪项开始。

## C. 迁回

按新的交出流程生成新批次。更新 `handoff_id`、设备、时间、分支、HEAD 和状态，不能把上一批入口原样改成“当前”。两台设备有不同未提交修改时先记录并停止自动合并，等待明确合并方向。

## 完成门槛

`README.md` 链接唯一当前任务；工作区状态、删除和未跟踪文件已记录；旧材料已有归档或逻辑退役登记；可上传配置无秘密、本地私密包已排除 Git；Git/remote/提交/推送事实与限制已记录；接手者能找到第一动作；未验证项没有写成完成；接收收尾明确续作授权边界。
