# 设备交接流程

设备交接用于换设备、迁回或离开当前设备后在另一台设备继续。它必须生成可脱离当前对话阅读的 `交接/`，并按固定命名规则输出。

## A. 交出设备

1. **只读基线**：读取项目 `AGENTS.md`、现行文档入口和当前 `交接/README.md`（如有）；记录项目路径、分支、HEAD、remote、Git/运行时版本；运行 `git status --short`、`git diff --check`，必要时记录 diff 统计。保留已有修改、删除和未跟踪文件。
2. **更新固定文件**：维护 `README.md`、`工作交接/任务交接.md`、`文件导航.md`、`环境与验证.md`、`归档索引.md`、`接收回执.md`；在任务交接的“对话关键结论”中保存尚未落入代码或正式文档的有效要求、决定理由与未决事项，并按目录契约记录关键时间线和取代关系。只保留一个当前计划入口；不再创建“最新方案/最终方案/当前交接”等并列文件。
3. **整理旧材料**：盘点旧计划和旧交接的未完成事项，先映射到任务 ID，再将安全的阶段材料移入 `工作交接/归档/<handoff_id>/`；项目规范、原始资料和受规则保护文件不覆盖、不改名，改在归档索引登记。
4. **配置交接**：按 [配置流程](config-handoff.md) 生成最小脱敏清单和恢复步骤。复制本 Skill 到 `交接/配置交接/skills/hand-off/`，排除 `.DS_Store`、缓存、凭证、父目录和其他 Skill 的运行时缓存。
5. **校验与 Git**：先运行校验脚本和秘密扫描，再按 [Git 流程](git-handoff.md) 检查、暂存、提交或推送。用户明确授权的完整设备交接可以继续执行对应 Git 动作；未授权时停在本地就绪。
6. **收尾**：按 [收尾报告](final-report.md) 给出状态、云端结果、未纳入内容和下一设备第一步。推送失败或未执行时不得称为“已部署”。

## B. 新设备接收

1. 从用户指定存档或远端恢复，先核对目标分支、实际 HEAD、工作区和本地未提交改动；不覆盖已有修改。
2. 只读 `交接/README.md`，按其中链接读取 `工作交接/任务交接.md`、`文件导航.md`、`环境与验证.md`、`归档索引.md` 和配置说明。
3. 运行校验脚本。失败先报告，不自动改写清单或原项目；绝对源路径只作为环境提示，不应误判为秘密。
4. 按白名单逐项恢复配置：先备份目标机现有配置，逐文件合并并验证；禁止整目录覆盖。
5. 先复核当前任务的最小基线，再执行任务账本中的第一动作。不要从归档恢复已退役计划。
6. 填写 `工作交接/接收回执.md`，新增接收方的实际路径、HEAD、校验结果、配置恢复结果和冲突；保留交出方快照不变。

## C. 迁回

按新的交出流程生成新批次。更新 `handoff_id`、设备、时间、分支、HEAD 和状态，不能把上一批入口原样改成“当前”。两台设备有不同未提交修改时先记录并停止自动合并，等待明确合并方向。

## 完成门槛

`README.md` 链接唯一当前任务；工作区状态、删除和未跟踪文件已记录；旧材料已有归档或逻辑退役登记；配置清单无秘密；Git/remote/提交/推送事实与限制已记录；接手者能找到第一动作；未验证项没有写成完成。
