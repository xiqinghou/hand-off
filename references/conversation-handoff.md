# 对话交接流程

对话交接用于同一项目内从一个 Codex 对话切换到另一个对话。它只传递任务上下文，默认不采集用户目录配置、不执行 GitHub 部署，因此比设备交接轻量。

## A. 交出对话

1. 读取项目 `AGENTS.md`、现行文档入口和 `交接/README.md`（如有），确认分支、HEAD、工作区摘要。
2. 更新共同入口及 `工作交接/任务交接.md`：记录用户目标、不可改变约束、整体计划、当前/中断任务、已修改文件、未跟踪/删除项、已验证证据、未决问题和第一动作；按目录契约维护“对话关键结论”，保留用户纠正、决定理由、否决方向、关键时间线和取代关系，区分当前有效要求与信息缺口。
3. 不新建“对话交接-当前、当前任务、最终摘要”等并列入口；保留 `工作交接/文件导航.md`、`环境与验证.md` 等固定文件，缺少时按最小模板补齐。
4. 识别阶段性计划和旧快照，先登记未完成义务，再安全归档到 `工作交接/归档/<handoff_id>/`；不改写正式规范。
5. 正文定稿后先运行 `validate_handoff.py <项目>/交接 --scene conversation --write-manifest`，再去掉 `--write-manifest` 复核。本场景不要求 Git commit、remote 检查或用户配置采集，除非用户另有明确要求。已有设备私密包原地保留，不读取内容、不复制到归档；校验仅检查其 Git 排除状态。

## B. 新对话接收

1. 先读 `交接/README.md`、项目规则和 `工作交接/任务交接.md`，确认场景、方向、HEAD 和限制。
2. 运行同一脚本的 `--scene conversation` 只读校验，不重建清单；对照当前代码检查快照是否过时，过时字段记入接收回执，不能静默采信。
3. 核对任务账本中的待办与中断进度，只做接收必需的小范围基线检查；报告已接收内容、疑问与建议首项，默认收到用户明确的“继续”后续作。用户本次已要求接手并继续时不重复等待；不要因为看到归档而恢复已退役任务。
4. 新一轮对话交出时生成新的批次，保留前一批快照和回执。

## 完成门槛

下一对话无需阅读原对话即可回答：现在做什么、已完成到哪里、哪些不能动、下一步是什么、哪些结果尚未验证。无法回答时状态只能是 `draft`。
