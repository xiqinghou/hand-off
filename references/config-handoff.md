# 配置交接与安全边界

配置交接只解决新设备恢复必要工作环境，不复制用户目录。默认采用“可携带的脱敏配置 + 新设备手动设置秘密”的方式；文件已复制不等于环境已恢复。

## 禁止纳入

以下内容不得写入 `交接/配置交接/`、Git 或压缩包：API key、token、密码、私钥、证书私密部分、OAuth 登录态、cookies、浏览器 profile、完整 `~/.codex`、历史会话、命令日志、缓存、临时文件、设备指纹以及含凭证的外部服务响应。

## 可纳入白名单

只有确认不含秘密且确有项目用途时才复制：

- 脱敏的 `config.toml` 或等价主配置；
- 不含密钥和登录态的模型/能力声明；
- 本项目需要的 Skill（包含 `SKILL.md`、引用和脚本，不复制插件缓存）；
- 项目所需的非敏感命令、环境变量名称、工具版本和跨平台恢复说明；
- 配置示例与逐项恢复步骤。

实际用户目录位置以目标环境为准（例如 `~/.codex` 或 `CODEX_HOME`），不能把当前用户名、绝对路径或机器名硬编码为必需条件。MCP 本地代码、运行时、依赖和注册项分别记录；不要携带失效绝对路径或盲目注册。

## 文件清单

设备交接固定使用 `配置交接/文件清单.json`，顶层为包含 `files` 数组的对象。`path` 相对 `配置交接/`，只能用 `/`；禁止绝对路径、`..`、软链接。每个实际包含文件必须登记真实 SHA-256，下面的说明值必须替换：

```json
{
  "files": [
    {
      "path": "codex/config.toml",
      "source": "~/.codex/config.toml",
      "purpose": "非敏感默认设置",
      "sensitivity": "sanitized",
      "included": true,
      "sha256": "定稿文件的64位小写十六进制SHA-256",
      "restore": "备份后逐项合并到目标配置目录"
    },
    {
      "path": "codex/auth.json",
      "source": "~/.codex/auth.json",
      "included": false,
      "reason": "登录凭证不携带；目标设备重新登录"
    }
  ]
}
```

未纳入但影响恢复的文件也登记 `included: false` 和原因，例如包含 API key，需在新设备通过安全方式手动设置。清单本身不得出现秘密值。

## 恢复步骤

新设备先备份已有配置，再逐文件合并；完成后核对 Codex 启动、Skill 可发现性、项目路径和工具版本。逐项记录“已恢复/未恢复/待人工设置”和证据。无法实际验证时状态保持 `ready_with_limits`，不写成“环境已恢复”。

本 Skill 副本放在 `配置交接/skills/hand-off/`。用户主要且确有使用的其他 Skill 也按白名单携带：逐项列出名称、来源、版本、依赖和恢复方法；不要仅凭“已安装”复制整个用户 Skill 库。本次完整配置交接已包含必要的非敏感配置采集，不为每个白名单文件反复请求同一许可。

保存副本不等于全局安装。目标客户端支持的 Skill 发现目录需按当前文档核对；本地原有 `~/.codex/skills` 路径是来源线索，不能直接假定每个客户端相同。用户可先让 Codex 直接读取便携副本的 `SKILL.md`；需要自动发现时，再安装到目标客户端实际支持的用户或项目目录，并验证。[官方 Skill 文档](https://developers.openai.com/codex/skills)
