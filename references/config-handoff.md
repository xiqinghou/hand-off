# 配置交接与本地恢复包

设备交接提供可上传的脱敏资料，以及用户授权后的最小私密恢复包。Skill 自动采集、整理并告诉用户复制哪个文件夹，用户无需到个人目录逐一找文件。修改 Skill 本身不等于启动实际采集。

## 两部分与固定位置

| 内容 | 项目内位置 | 传输方式 |
|---|---|---|
| 恢复说明、非敏感清单 | `配置交接/README.md`、`配置交接/文件清单.json` | Git/GitHub |
| 脱敏配置、便携 Skill | `配置交接/codex/`、`配置交接/skills/hand-off/` | Git/GitHub |
| 含实际 API 密钥的最小配置与 Skill | `配置交接/.codex/` | U 盘/受控本地传输；Git 排除 |

`.codex/` 不是整个用户目录副本。典型内容为 `config.toml`、必要的 `models.json`、仅 API-key 认证所需的最小 `auth.json`、`skills/hand-off/`、`README.md` 和本地 `文件清单.json`。其他确有需要的 Skill、配置及环境变量恢复脚本按用途白名单加入。

不可采集 OAuth 登录态、refresh/access/id token、cookies、浏览器 profile、私钥、会话数据库、完整历史、日志、缓存、设备指纹或整个插件目录。系统凭据库不能靠文件复制迁移；无法读取必要 API 密钥时明确缺项，不要求用户在对话里粘贴密钥。

## 先排除 Git，再采集

1. 在项目 `.gitignore` 登记 `/交接/配置交接/.codex/`，保留已有规则。目录不同则使用实际相对路径。
2. 用 `git ls-files` 确认子树没有已跟踪/已暂存文件，`git check-ignore` 确认实际路径受排除。`.gitignore` 不会移除已跟踪文件；若已跟踪，暂停采集与推送，报告问题，不自动重写历史。
3. 用户明确要求携带完整可用配置时执行采集，不反复询问每个必要文件；只要脱敏资料时不生成私密包。仓库私有不代表授权把密钥加入 Git。
4. POSIX 私密目录使用 700、敏感文件使用 600；其他系统按实际权限说明限制。只展示位置、状态、数量及校验结果，不回显秘密或文件正文。

## 自动生成最小配置

- 从实际 `CODEX_HOME`/用户配置目录读取，源文件保持不变。保留当前需要的中转地址、模型、认证方式、偏好和 Skill；用结构化解析保留语义，不凭字符串截取破坏 TOML/JSON。
- 私密包保留启动所需的实际 API 密钥。文件式 API-key 认证仅导出必需键值到最小 `auth.json`，不复制账号 token。中转站使用哪个字段，以当前可验证的设置为准，不假定所有服务相同。
- 密钥只在环境变量中时，仅采集配置明确引用且已授权的变量，生成包内恢复/启动脚本或客户端支持的配置。不能把子进程环境设置误认为 Codex 主进程已经取得密钥；脚本不硬编码源设备用户名和路径。
- 识别 MCP、本地命令和绝对路径，记录目标机需要调整的路径和工具。配置存在不等于依赖已安装，不保证跨系统原样覆盖可用。
- 复制完整 `hand-off` 及确需的 Skill，不复制缓存。`.codex/skills` 是包内布局，目标发现目录可能为 `.agents/skills` 等，以客户端实际支持为准。
- 同时生成云端脱敏配置。其内容、说明、Git URL、清单、归档和公开 Skill 不得带秘密；不得把私密包复制进普通归档或云端压缩包。
- 可上传入口只用文字标注可选的本地包路径，不将 `.codex/` 设为必需的本地链接目标，避免仅云端接收时入口链接失效；交出回复仍提供用户可点击的实际路径。
- 已有私密包时先核对批次和范围，只替换本次明确管理的配置，未知文件不得静默删除。旧配置未更新或密钥缺失时显式报告，不能把旧包当成新包就绪。

## 两份清单

云端 `配置交接/文件清单.json` 保持 `files` 数组结构。可上传文件使用 `included: true` 及真实 SHA-256；仅本地携带的文件登记 `included: false`、`transport: local_only` 和原因，不填写秘密值。`included` 表示纳入云端包，不代表源设备文件不存在。

```json
{
  "files": [
    {
      "path": "codex/config.toml",
      "included": true,
      "sensitivity": "sanitized",
      "sha256": "定稿文件的64位小写十六进制SHA-256"
    },
    {
      "path": ".codex/auth.json",
      "included": false,
      "transport": "local_only",
      "reason": "仅随本地恢复包携带，不纳入 Git"
    }
  ]
}
```

私密包内 `.codex/文件清单.json` 由 `validate_handoff.py --private-config --write-manifest` 生成，覆盖文件 SHA-256、大小和相对路径，自身不纳入。私密包不进入公共 `校验清单.json`。接收时两份清单都只校验，不重建。

## 用户复制与新设备恢复

交出报告链接 `.codex/` 的绝对路径，说明它是隐藏文件夹，用户可显示隐藏项或打开该路径，将整个最小包复制到 U 盘。明确“含真实密钥，仅本地携带，未上传”；仅有脱敏包时说明还需设置认证。

新设备先安装兼容 Codex。用户可在尚无法使用 Codex 时手动恢复：

1. 退出 Codex，备份目标已有配置。无配置时直接放入必要文件；已有配置时用包内列出的同名配置文件覆盖并保留其他文件，不能用“替换整个文件夹”删除原目录。
2. 只恢复清单里的配置和 Skill，不把包内 `README.md`、`文件清单.json` 当成运行配置。按实际发现目录放置 Skill，按说明导入必要环境变量，调整系统/用户名相关路径。
3. 重启 Codex，验证能正常对话、能识别 `hand-off`。GitHub 私有仓库权限另行登录，中转 API 凭据不能代替。
4. 拉取项目，将 U 盘包放回项目 `交接/配置交接/.codex/`（如要校验包），说“帮我接手来自另一台设备的交接资料”。Skill 自动定位入口，校验完整性和 Git 排除，再复核环境；已恢复内容不重复覆盖。

文件已生成、用户已复制、目标已恢复、服务可用分别记录；不能替用户声称 U 盘已复制或目标已启动。没有实际服务/设备证据时保持 `ready_with_limits`。仅从云端接收且没带 U 盘包时说明“私密包不在云端，需要本地携带或重新设置凭据”。
