# hand-off

让 Codex 在换电脑或换对话时接住项目资料、任务进度和关键决定。你说明要交出还是接收，Skill 负责整理与核对，最后给出清晰的交接报告。

这是一套中文 Codex Skill，配有本地 Python 校验工具；它指导 AI 完成交接，不是搬运整台电脑或恢复完整聊天记录的程序。

## 两种场景

| 场景 | 适合什么时候 | 交接范围 |
|---|---|---|
| 设备交接 | 换电脑、迁回原设备、离开当前设备 | 项目与任务状态、关键决定、最小配置、Skill、环境说明，以及授权范围内的 Git/GitHub 同步 |
| 对话交接 | 同一项目换一个 Codex 对话 | 项目入口、任务进度、关键决定、待办与下一步；默认不采集用户配置、不提交推送 |

用户已说清场景与方向就直接执行；只说“帮我交接”时，才补问设备还是对话、交出还是接收。执行前会提醒建议的主代理模型与推理强度。

## 安装

下载本仓库后，让 Codex 读取 [SKILL.md](SKILL.md) 即可按流程使用。需要长期使用，可对 Codex 说：

> 使用 $skill-installer，安装 https://github.com/xiqinghou/hand-off 仓库根目录中的 hand-off Skill。

也可将 `SKILL.md`、`agents/`、`references/`、`scripts/` 和本说明放入客户端支持的 Skill 目录下的 `hand-off/`。当前官方文档使用用户目录 `~/.agents/skills/`；部分安装环境使用 `$CODEX_HOME/skills/` 或 `~/.codex/skills/`。按实际客户端确认发现路径，避免重复安装。

安装后在下一轮对话尝试输入 `$hand-off`；未发现时刷新或重启客户端。参见 [官方 Skill 文档](https://developers.openai.com/codex/skills)。

## 用户怎么用

### 设备交出：离开旧电脑前

1. 在当前项目中唤出 `$hand-off`，说：“我准备去另一台设备工作，帮我进行交接。”首次需要完整配置时补充：“把启动所需的真实 API 配置也整理好，供我用 U 盘携带。”已明确授权的偏好无需每次重复。
2. Skill 整理项目导航、唯一计划、已完成与未完成任务、中断位置、关键决定时间线；归档旧执行材料，核心规范与用户原件保持原状。
3. 按授权生成最小配置、校验资料，完成必要的 Git 提交与云端同步。真实 API 配置放在本地私密包，先排除 Git，不能因仓库私有就自动上传密钥。
4. 查看交出报告。需要 U 盘迁移时，从报告链接打开 `交接/配置交接/.codex/`，将这个最小包复制到 U 盘；不用再到个人目录逐个寻找文件。它是隐藏目录，macOS 可用 `Command + Shift + .`、Windows 可打开“显示隐藏的项目”。

报告分别说明本地包是否就绪、云端是否同步、哪些资料仍只在本机、哪里尚未验证。Skill 不会在没有证据时声称 U 盘已复制或新电脑已恢复。

### 设备接收：到达新电脑后

1. 安装兼容的 Codex。若中转 API 配置未恢复导致 Codex 无法使用，先退出 Codex、备份目标原配置，再按 U 盘包内说明复制清单中的同名配置文件；保留目标目录中的其他内容，不删除替换整个配置目录。恢复必要环境变量与 Skill，按新系统调整路径。
2. 启动 Codex，确认可以正常对话，并能唤出 `$hand-off`。包内 Skill 已随行，但实际发现目录要以目标客户端为准；复制完不等于一定能自动识别。GitHub 私有仓库访问仍需单独登录。
3. 告诉 Codex 仓库地址，让它拉取项目并打开项目工作目录。已有本地项目时先核对，避免覆盖修改；U 盘包也可放回 `交接/配置交接/.codex/`，供额外完整性校验。
4. 唤出 `$hand-off`，只需说：“帮我接手来自另一个设备上的交接资料。”它会从当前项目的 `交接/README.md` 自动读取，核对批次、分支、文件、任务与必要环境。只有入口找不到、存在多个候选项目或项目未拉取时，才补问必要信息。
5. 查看接收简报：已接收哪些资料、计划中还有哪些待办、上次中断在哪里、有什么疑问，以及建议先做哪项。默认此时尚未开始执行待办；你说“继续”或“继续 T-xxx”后，才执行未完成工作。本次已明确说“接手并继续”时会按授权直接续作。

还未安装 Skill 时，可让 Codex 直接读取项目内的 `交接/配置交接/skills/hand-off/SKILL.md`。只用云端资料也可恢复任务上下文，但云端不含真实密钥；没有携带私密包且目标无可用凭据时，需要另外恢复认证。

### 对话交接：同一项目换对话

1. 旧对话唤出 `$hand-off`，说：“我要换一个对话，帮我交接当前工作。”
2. 新对话打开同一项目，唤出 `$hand-off`，说：“帮我接手来自另一个对话的交接资料。”
3. 查看接收简报，再说“继续”。默认不复制个人配置、不做设备部署或 GitHub 同步。

## 交接资料放在哪里

目录生成在业务项目中，**不是这个 Skill 源码仓库**：

```text
交接/
├── README.md                  # 唯一接收入口
├── 校验清单.json               # 可上传资料的完整性清单
├── 工作交接/
│   ├── 任务交接.md             # 计划、任务、中断进度、关键决定时间线
│   ├── 文件导航.md
│   ├── 环境与验证.md
│   ├── 归档索引.md
│   ├── 接收回执.md
│   └── 归档/                  # 按历史批次保存
└── 配置交接/
    ├── README.md              # 配置恢复说明
    ├── 文件清单.json           # 设备交接的云端配置清单
    ├── codex/                 # 可上传的脱敏配置
    ├── skills/hand-off/       # 可上传的便携 Skill
    └── .codex/                # 可选：含真实 API 配置，仅本地/U 盘
        ├── config.toml
        ├── auth.json          # 必要的最小 API-key 认证（如适用）
        ├── README.md
        ├── 文件清单.json       # 私密包独立校验清单
        └── skills/hand-off/
```

固定文件名避免多份“最终版”。旧计划的剩余工作先映射到现行任务，再归档；新 AI 从唯一入口即可接管，不必沿着多份旧交接逐一查找。当前有效决定优先展示，后来的 AI 建议不会自动覆盖用户决定。

## 校验工具

需要 Python 3.10 或更高版本与 Git；脚本仅使用 Python 标准库。Git 查询为只读，不采集配置、不访问账户或网络、不执行提交推送。

交出时，正文定稿后生成清单，再只读复核：

```sh
python3 -B scripts/validate_handoff.py /path/to/project/交接 --scene device --write-manifest
python3 -B scripts/validate_handoff.py /path/to/project/交接 --scene device
```

含本地私密包时，两条命令都加 `--private-config`，分别生成/核验两份清单。仅从云端接收时不加该参数；对话场景将 `device` 改成 `conversation`。接收时不要使用 `--write-manifest`，以免掩盖文件变化。

工具检查必需文件、README 本地链接、配置清单、常见秘密特征、路径边界、软链接和 SHA-256；私密目录还要验证未被 Git 跟踪且实际文件均受忽略。只有指定的私密配置允许 API 密钥，其说明、Skill 与清单仍不能带秘密。警告需要人工复核；扫描不保证发现所有秘密，哈希不证明来源可信，脚本不能判断业务任务完成或对话结论正确。

## 开发与验证

```sh
python3 -B scripts/test_validate_handoff.py
```

回归测试使用临时目录和临时 Git 仓库、虚构凭据，不访问账户、不更改真实项目。持续集成配置为 Linux 上的 Python 3.10 和 3.12，实际通过情况以仓库 Actions 结果为准；这不等同于完整设备迁移实测。修改流程说明后，仍需核对场景识别、授权边界和简报内容。

模型建议见 [模型与分工](references/model-routing.md)。其中具体模型名称是可调整的示例，以运行环境实际可用模型为准，不代表所有账户均支持，也不是性能保证。

## 使用边界

- 真实 API 配置仅放在经授权、Git 忽略的最小本地恢复包；不上传密钥、私钥、登录态或完整会话数据库。
- GitHub 登录、系统权限、无法自动合并的冲突可能需要用户处理。
- 已有修改和未跟踪文件不会为了整理而被擅自清理。
- 未能读取的历史会明确标注，不宣称完整恢复记忆。
- “交接已接收”“待办已开始”“业务任务完成”“目标设备实测可用”分别记录。
