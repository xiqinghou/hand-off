# hand-off

让 Codex 在换电脑或换对话时接着做，保留任务进度、关键决定和可核查的交接材料。

hand-off 是一套中文 Codex Skill，配有本地 Python 校验工具。它指导 AI 完成交接，不是自动搬运整台电脑或恢复完整聊天记录的程序。

## 两种场景

| 场景 | 适合什么时候 | 交接范围 |
|---|---|---|
| 设备交接 | 换电脑、迁回原设备、离开当前设备 | 工作状态、必要的脱敏配置、Skill、环境恢复说明，以及授权范围内的 Git/GitHub 同步 |
| 对话交接 | 同一项目换一个 Codex 对话继续 | 任务上下文、关键决定、文件导航和下一步；默认不采集用户配置、不提交推送 |

## 安装

下载本仓库后，让 Codex 读取根目录的 [SKILL.md](SKILL.md) 即可按流程使用。

需要长期使用，可对 Codex 说：

> 使用 $skill-installer，安装这个 GitHub 仓库根目录中的 hand-off Skill。

同时提供本仓库地址。也可将仓库中的 `SKILL.md`、`agents/`、`references/` 和 `scripts/` 放入客户端支持的 Skill 目录下的 `hand-off/`。当前官方文档使用用户目录 `~/.agents/skills/`；部分安装环境使用 `$CODEX_HOME/skills/` 或 `~/.codex/skills/`。按实际客户端确认发现路径，避免重复安装。

安装后尝试输入 `$hand-off`；未发现时刷新或重启客户端。参见 [官方 Skill 文档](https://developers.openai.com/codex/skills)。

## 使用

准备离开：

> 使用 $hand-off，帮我准备交接。

同项目换对话：

> 使用 $hand-off，准备一次对话交接，保留当前任务和决定时间线。

新设备接收：

> 使用 $hand-off，进行设备交接接收。读取项目中的交接/README.md，先核对交接包和实际工作区，再从任务交接中的第一步继续。

还未安装 Skill 的新设备，可直接让 Codex 读取交接包内的 `交接/配置交接/skills/hand-off/SKILL.md`。

## 完整流程

1. 选择设备交接或对话交接，确认交出/接收方向，提醒建议模型与推理强度。
2. 盘点项目结构、整体计划、当前任务、未提交成果和证据。
3. 提取可访问对话中的关键要求与决定，记录时间、状态、取代关系和信息缺口。
4. 汇总当前有效执行入口，接住未完成义务后再归档旧计划，保护核心规范与原件。
5. 按场景整理必要配置与恢复说明；只在授权范围内安装工具、提交和推送。
6. 校验交接包，给用户清晰报告：已完成、未验证、云端状态、本机独有内容和下一步。
7. 接收方检查实际状态，按需恢复环境，记录接收回执并继续工作。

交接时生成的目录位于业务项目中，**不是这个 Skill 源码仓库**：

```text
交接/
├── README.md
├── 校验清单.json
├── 工作交接/
│   ├── 任务交接.md
│   ├── 文件导航.md
│   ├── 环境与验证.md
│   ├── 归档索引.md
│   ├── 接收回执.md
│   └── 归档/
└── 配置交接/
    ├── README.md
    ├── 文件清单.json         # 设备交接
    ├── codex/               # 必要的脱敏配置
    └── skills/hand-off/     # 便携 Skill
```

固定文件名避免多份“最终版”；归档按批次保存。当前有效结论优先展示，后来的 AI 建议不会自动覆盖用户决定。

## 校验工具

需要 Python 3.10 或更高版本；校验脚本仅使用标准库。

交出时，正文定稿后生成清单，再只读复核：

```sh
python3 -B scripts/validate_handoff.py /path/to/project/交接 --scene device --write-manifest
python3 -B scripts/validate_handoff.py /path/to/project/交接 --scene device
```

对话场景将 `device` 改成 `conversation`。接收时不要使用 `--write-manifest`，以免掩盖文件变化。

工具检查必需文件、README 本地链接、配置清单、常见秘密特征、路径边界、软链接和 SHA-256 完整性。警告需要人工复核；哈希不证明来源可信，扫描不保证发现所有秘密，脚本不能判断业务任务完成或对话结论正确。

## 开发与验证

```sh
python3 -B scripts/test_validate_handoff.py
```

19 项回归测试使用临时目录，不运行 Git、不访问账户、不更改真实项目。持续集成配置为 Linux 上的 Python 3.10 和 3.12，实际通过情况以仓库 Actions 结果为准；这不等同于完整设备迁移实测。修改说明文件后，仍需人工核对流程语义。

模型建议见 [模型与分工](references/model-routing.md)。其中具体模型名称属于可调整的示例配置，以运行环境实际可用模型为准，不代表所有账户都支持，也不是性能保证。

## 使用边界

- 不上传密钥、私钥、登录态、完整用户配置目录或完整会话数据库。
- GitHub 登录、系统权限、无法自动合并的冲突可能需要用户处理。
- 已有修改和未跟踪文件不会为了整理而被擅自清理。
- 未能读取的历史会明确标注，不宣称完整恢复记忆。
- “交接就绪”与“业务任务完成”“目标设备已验证”分别记录。

欢迎通过 Issue 提交脱敏的复现步骤或提出改进，通过 Pull Request 贡献修复。请勿在公开 Issue 中粘贴凭证或私人项目交接内容。
